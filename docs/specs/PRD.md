# Tank-Game MVP PRD

## 背景

Tank-Game 当前已经整理成一个可展示的规则 Bot 项目。主策略集中在 `src/bots/xjy.py` 中，能够根据裁判传入的 JSON 状态返回移动方向。它的核心价值是规则约束下的实时决策，而不是深度学习或完整游戏引擎。

现在的问题不是缺少更多策略点，而是工程结构还不适合长期迭代：主逻辑集中在一个文件里，缺少面向模块的测试，也缺少给未来开发者或 AI Coding 代理使用的需求边界。

## 用户和读者

- 作品集读者：希望快速理解项目做了什么、为什么值得看、技术重点在哪里。
- 未来维护者：需要知道哪些行为不能随意改，如何安全拆分和扩展策略。
- AI Coding 代理：需要明确任务边界、验收标准和禁止事项，避免一次性大重写。

## 问题

- `xjy.py` 同时承担裁判 I/O、状态维护、规则判断、危险判断、路径搜索和评分。
- 策略参数和方向常量混在入口文件中，后续修改容易引入回归。
- 没有最小测试覆盖核心规则，例如反向限制、子弹两格移动、墙体阻挡和死胡同判断。
- 项目文档说明了现状，但还没有定义下一阶段可执行的 MVP。

## MVP 目标

MVP 的目标是完成结构化重构，同时保持原有策略行为。

成功标准：

- `TankAI.get_action(state)` 的外部接口不变。
- 原有策略意图保留：合法性检查、子弹规避、DFS 生存深度、BFS 机动性、瞄准奖励、方向连续性。
- 新增 `src/tank_ai/` 模块，把规则、危险、机动性、陷阱和评分拆清楚。
- 新增最小测试，覆盖关键规则和回归风险。
- 文档说明后续 AI Coding 如何继续小步开发。

## 非目标

- 不训练机器学习模型。
- 不重写裁判程序。
- 不新增复杂可视化或回放系统。
- 不调整策略权重来追求短期胜率。
- 不改动根目录 `README.md` 的定位。

## 约束

- 裁判仍通过标准输入输出和 Bot 通信。
- Bot 返回值仍只能是 `UP`、`DOWN`、`LEFT`、`RIGHT`。
- 公开配置不能依赖被 `.gitignore` 排除的本地 archive 文件。
- 每次重构必须能通过语法检查和最小测试。
